# ТЗ: Jev (TypeSafe System One) как инструмент проверки игры

Дата: 2026-09-21. Статус: **ворота калибровки пройдены — можно строить пайплайн**.
Проверка маршрутов: `node scripts/jev-route-probe.mjs`.
Рабочие правила и доказательства: `scripts/jev/README.md`.

---

## 1. Короткий вывод

**Jev — не LLM и не «модель для кода».** Это модель решений: ей дают состояние
(`state`) и типизированные вопросы, она возвращает решение с вероятностями.
Три примитива: `Choice` (выбрать из вариантов), `Score` (оценить по рубрике),
`Noul` (да/нет с вероятностью). Она **не пишет код, не играет партии и не рассуждает
цепочкой** — она выносит одно узкое суждение по тексту, который ей дали.

**Главное, что выяснилось на живом API: Jev не считает — он судит.** Первый прогон
калибровки дал все 20 карт в диапазоне 2.09–2.15 при уверенности 0.64: середина шкалы.
Причина оказалась не в языке и не в модели, а в постановке задачи — я просил её самой
вычислить сумму статов и сравнить с нормой. Когда арифметику посчитал код, а модели
осталось только суждение, результат стал **20/20 в трёх прогонах без единого
расхождения**. Это штатный режим Jev: TypeSafe называет принцип «keep code in control».

**Что даёт Jev игре:** калиброванное второе мнение там, где у нас нет детерминированной
проверки — оценка силы карт, разбор ходов ИИ, разметка неоднозначных правил.
51 боевой тест остаётся эталоном; Jev ищет то, чего в тестах нет.

### 2.1. Четыре правила работы — выведены из проб, не из документации

| Правило | Доказательство |
|---|---|
| **Числа считает код.** Модели отдаём готовые значения | с сырыми данными 13/20, с посчитанными — 20/20 |
| **Состояние — простой строкой**, не JSON-объектом | объект: 0.73 / 0.89; та же мысль строкой: 0.97 / 0.97 |
| **Noul вместо Score** для оценок | Score по шкале 5 или 3 уровней: разброс 0.06–0.09 (середина шкалы); Noul: разделение классов 0.95 |
| **Решение принимает код** по вероятности | порог 0.5 в коде, а не «мнение модели» |

Что проверено и работает: Noul «кот спит» / «кот летит» — 0.98 / 0.01 на английском и
0.97 / 0.01 **на русском**; Choice — `tomato` с уверенностью 1.00; Score на двух
конкретных уровнях — 1 и 0 с уверенностью 1.00; суждение о балансе по готовым числам —
20/20, вероятности 0.98 против 0.03, корреляция сигнала r = −0.830.

**Русский язык работает не хуже английского** (разница 0.01–0.05) — риск, которого я
боялся в первой редакции этого ТЗ, не подтвердился.

## 3. Что модель умеет и чего не умеет — границы

| Умеет | Не умеет |
|---|---|
| Выбрать один вариант из заданного списка с вероятностями по каждому | Писать и править код |
| Оценить объект по нашей рубрике (Score с уровнями) | Прогонять партии, считать вероятности побед |
| Ответить да/нет с калиброванной вероятностью | Помнить контекст между запросами |
| Разложить одно большое суждение на атомарные вопросы в одном запросе | Читать картинки, аудио, видео — только текст |
| Держать 64k токенов на запрос (32k — состояние + самый длинный вопрос) | Гарантировать правильность: 96% — это не обещание |

**Два ограничения, которые прямо касаются нас:**

1. **Английский — основной язык обучения, качество на других ниже.** Вся игра на
   русском: названия карт, тексты способностей, подсказки. Это был главный риск проекта,
   поэтому первым шагом шла калибровка на русском. **Проверено: риск не подтвердился** —
   русский дал 0.97 против 0.98 на английском, разница в пределах шума.
2. **Jev не видит игру и не считает.** Он судит наш *текстовый пересказ* состояния, а
   арифметику обязан сделать код до запроса. Качество суждения упирается в качество
   выгрузки состояния — это работа на нашей стороне, а не на стороне модели.

## 4. Направления применения — по цене и по отдаче

Объём карт для расчётов измерен по коду: **75 карт** (39 существ, 21 заклинание,
9 чар, 6 земель), кривая маны 0–9. Эталон правил — **51 боевой тест**.

### А. Оценка ходов ИИ («Хранителя») — высокая отдача, средняя работа

- **Состояние:** столешница, рука, мана, здоровье, доступные ходы A/B/C — текстом, с уже
  посчитанными числами (урон, размен, остаток маны).
- **Вопрос:** `Choice` «какой из доступных ходов сильнее» (все варианты даёт код) и `Noul`
  «есть ли среди доступных ходов явно сильнее выбранного».
- **Важно:** варианты ходов и их оценку готовит код. Если попросить модель самой
  перечислить ходы, она начнёт считать — и результат будет как в провалившемся прогоне.
- **Зачем:** наш `src/game/ai.ts` (693 строки) — эвристика без обратной связи. Jev даёт
  второе мнение по позициям, где ИИ, возможно, ошибся.
- **Проверка:** расхождения с выбором ИИ → смотрим глазами → подтверждённые ошибки
  становятся регрессионными тестами (детерминированными, без модели).
- **Цена:** ~800 токенов на позицию; 200 позиций ≈ 160 тыс. токенов ≈ **$0.007**.

### Б. Баланс карт — высокая отдача, низкая работа. **Ворота пройдены**

- **Состояние:** по карте — имя, цена, тип, атака/здоровье, ключевые слова, текст
  способности **плюс посчитанные кодом** сумма статов, норма для цены и разница.
- **Вопрос:** `Noul` «разница отрицательная настолько, что карта не окупает ману
  (разница −2 или хуже)?» — с явными критериями для «да» и «нет».
- **Результат проверки:** **20/20, три прогона без расхождений**, вероятности 0.98 для
  слабых карт против 0.03 для нормальных, корреляция сигнала r = −0.830.
- **Чего НЕ делать:** `Score` «сила за свою цену» по 5 или 3 уровням — обе формы дали
  разброс 0.06–0.09, то есть середину шкалы. Проверено и отброшено.
- **Зачем:** даёт список выбросов для ручного разбора. Решение о правке баланса
  принимает человек, модель только указывает, куда смотреть.
- **Цена:** измерено — полный проход 75 карт ≈ **$0.0009**.

### В. Согласованность правил — средняя отдача, низкая работа

- **Состояние:** сценарий из движка (например: «существо с первым ударом и смертельным
  касанием атакует существо 3/3; что происходит с блокирующим») — простой строкой.
- **Вопрос:** `Noul` «следует ли блокирующий умереть до нанесения урона».
- **Зачем:** 51 тест — наша точка истины, но он покрывает не все стыки. Jev размечает
  неоднозначные, кандидаты уходят в тесты.
- **Осторожно:** здесь модель может быть права, а мы нет — и наоборот. Расхождение
  разбирается человеком, автоматически правила не меняются.
- **Цена:** ~400 токенов на сценарий; 100 сценариев ≈ 40 тыс. токенов ≈ **$0.002**.

### Г. Тексты интерфейса — низкая отдача, разовая

- **Состояние:** тексты подсказок обучения (только что переписанных) и карт.
- **Вопрос:** `Noul` «понятно ли новичку, что делать» (бинарно, не «оцените ясность»).
- **Зачем:** разовая вычитка на двусмысленности.
- **Цена:** ~300 токенов на текст; 100 текстов ≈ 30 тыс. токенов ≈ **$0.001**.

**Итого весь объём ТЗ: ≈ 270 тыс. токенов ≈ $0.011.** При кредите $5 это 0.2% —
то есть цена не является ограничением вообще. Ограничение — время на выгрузку
состояния и на разбор того, что модель ответила.

## 5. Архитектура: Jev только вне игры

**Жёсткое правило: модель не попадает в игровой рантайм.** Ни в бой, ни в ИИ, ни в UI.
Причины: задержка в бою, зависимость живого сайта от внешнего API и невозможность
воспроизвести вывод. Jev живёт только в офлайн-скриптах проверки — там, где мы
запускаем его сами и читаем ответ глазами.

```
данные из кода      →  jev/client.mjs   →  POST /v1/systemone  →  ответ с вероятностями
(числа считает КОД)     (тонкая обёртка)                            ↓
состояние СТРОКОЙ                                          порог вероятности в КОДЕ
                                                            (не в модели)
                                                            ↓
                                                      отчёт для человека
```

Порог решает наш код, а не модель: вероятность ниже порога → в список «на проверку
человеком», выше → в список «вероятные находки». Это приём, который TypeSafe называет
confidence-gated routing.

**Два правила формы, без которых не работает** (доказательства в `scripts/jev/README.md`):

- **Числа считает код.** В состояние идут уже посчитанные значения. Если модель должна
  сложить 1 + 1 и сравнить с 4 — она ошибётся, и это выглядит как «модель сломана».
- **Состояние — простой строкой.** JSON-объект дал 0.73 / 0.89 там, где та же мысль
  строкой дала 0.97 / 0.97.
