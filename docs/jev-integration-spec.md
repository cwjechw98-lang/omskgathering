# ТЗ: Jev (TypeSafe System One) как инструмент проверки игры

Дата: 2026-09-21. Статус: **промежуточный этап — только доступ и калибровка**.
Проверка маршрутов: `node scripts/jev-route-probe.mjs`.

---

## 1. Короткий вывод

**Jev — не LLM и не «модель для кода».** Это модель решений: ей дают состояние
(`state`) и типизированные вопросы, она возвращает решение с вероятностями.
Три примитива: `Choice` (выбрать из вариантов), `Score` (оценить по рубрике),
`Noul` (да/нет с вероятностью). Она **не пишет код, не играет партии и не рассуждает
цепочкой** — она выносит одно узкое суждение по тексту, который ей дали.

**Главное, что нужно знать до начала работы: сейчас Jev недоступен ни по одному
маршруту из харнесса.** Это не предположение, а результат проверки (раздел 2).
Поэтому первым шагом ТЗ стоит не интеграция, а доступ.

**Что даёт Jev игре:** калиброванное второе мнение там, где у нас нет детерминированной
проверки — оценка силы карт по рубрике, разбор ходов ИИ, разметка неоднозначных правил.
51 боевой тест остаётся эталоном; Jev ищет то, чего в тестах нет.

## 3. Что модель умеет и чего не умеет — границы

| Умеет | Не умеет |
|---|---|
| Выбрать один вариант из заданного списка с вероятностями по каждому | Писать и править код |
| Оценить объект по нашей рубрике (Score с уровнями) | Прогонять партии, считать вероятности побед |
| Ответить да/нет с калиброванной вероятностью | Помнить контекст между запросами |
| Разложить одно большое суждение на атомарные вопросы в одном запросе | Читать картинки, аудио, видео — только текст |
| Держать 64k токенов на запрос (32k — состояние + самый длинный вопрос) | Гарантировать правильность: 96% — это не обещание |

**Два ограничения, которые прямо касаются нас:**

1. **Английский — основной язык обучения, качество на других ниже.** Вся игра на
   русском: названия карт, тексты способностей, подсказки. Это главный риск проекта,
   и поэтому в плане первым идёт не пайплайн, а калибровка на русском.
2. **Jev не видит игру.** Он судит наш *текстовый пересказ* состояния. Значит качество
   суждения упирается в качество выгрузки состояния — это работа на нашей стороне, а не
   на стороне модели.

## 4. Направления применения — по цене и по отдаче

Объём карт для расчётов измерен по коду: **75 карт** (39 существ, 21 заклинание,
9 чар, 6 земель), кривая маны 0–9. Эталон правил — **51 боевой тест**.

### А. Оценка ходов ИИ («Хранителя») — высокая отдача, средняя работа

- **Состояние:** столешница, рука, мана, здоровье, доступные ходы A/B/C — текстом.
- **Вопрос:** `Choice` из доступных ходов + `Score` «насколько ход сильный» + `Noul`
  «есть ли среди доступных ходов явно сильнее выбранного».
- **Зачем:** наш `src/game/ai.ts` (693 строки) — эвристика без обратной связи. Jev даёт
  второе мнение по каждой позиции, где ИИ ошибся.
- **Проверка:** расхождения с выбором ИИ → смотрим глазами → подтверждённые ошибки
  становятся регрессионными тестами (детерминированными, без модели).
- **Цена:** ~800 токенов на позицию; 200 позиций ≈ 160 тыс. токенов ≈ **$0.007**.

### Б. Баланс карт — высокая отдача, низкая работа

- **Состояние:** по карте — имя, цена, тип, атака/здоровье, ключевые слова, текст
  способности; в одном запросе пачка карт.
- **Вопросы:** `Score` «сила за свою цену» (5 уровней: слабая → сломанная) и `Noul`
  «выглядит ли карта нечестной для своей цены»; отдельно `Choice` «какой архетип».
- **Зачем:** даёт список выбросов для ручного разбора. Решение о правке баланса
  принимает человек, модель только указывает, куда смотреть.
- **Цена:** ~500 токенов на карту; полный проход 75 карт ≈ 37.5 тыс. токенов ≈ **$0.002**.

### В. Согласованность правил — средняя отдача, низкая работа

- **Состояние:** сценарий из движка (например: «существо с первым ударом и смертельным
  касанием атакует существо 3/3; что происходит с блокирующим»).
- **Вопрос:** `Noul` «следует ли блокирующий умереть до нанесения урона».
- **Зачем:** 51 тест — наша точка истины, но он покрывает не все стыки. Jev размечает
  неоднозначные, кандидаты уходят в тесты.
- **Осторожно:** здесь модель может быть права, а мы нет — и наоборот. Расхождение
  разбирается человеком, автоматически правила не меняются.
- **Цена:** ~400 токенов на сценарий; 100 сценариев ≈ 40 тыс. токенов ≈ **$0.002**.

### Г. Тексты интерфейса — низкая отдача, разовая

- **Состояние:** тексты подсказок обучения (только что переписанных) и карт.
- **Вопрос:** `Noul` «понятно ли новичку, что делать» + `Score` «ясность».
- **Зачем:** разовая вычитка на двусмысленности.
- **Цена:** ~300 токенов на текст; 100 текстов ≈ 30 тыс. токенов ≈ **$0.001**.

**Итого весь объём ТЗ: ≈ 270 тыс. токенов ≈ $0.011.** При кредите $5 это 0.2% —
то есть цена не является ограничением вообще. Ограничение — время на выгрузку
состояния и на разбор того, что модель ответила.

## 5. Архитектура: Jev только вне игры

**Жёсткое правило: модель не попадает в игровой рантайм.** Ни в бой, ни в ИИ, ни в UI.
Причины: задержка в бою, зависимость живого сайта от внешнего API и невозможность
воспроизвести вывод. Jev живёт только в офлайн-скриптах проверки — там, где мы
запускаем его сами и читаем ответ глазами.

```
состояние из кода  →  jev-client.mjs  →  POST /v1/systemone  →  ответ с вероятностями
(детерминированно)     (тонкая обёртка)                            ↓
                                                          порог уверенности в КОДЕ
                                                          (не в модели)
                                                          ↓
                                                    отчёт для человека
```

Порог уверенности решает наш код, а не модель: `confidence < 0.6` → в список
«на проверку человеком», выше — в список «вероятные находки». Это ровно тот приём,
который TypeSafe называет confidence-gated routing.

## 6. План: два шага, первый — ворота

### Шаг 1. Доступ и калибровка (обязательные ворота)

1. Получить `TYPESAFE_API_KEY` в [консоли](https://console.typesafe.ai/), положить в
   `~/.dsh/.credentials.yaml` (не в репозиторий).
2. Прогнать `node scripts/jev-route-probe.mjs` — все маршруты должны стать зелёными.
3. **Калибровка на русском** — то, ради чего этот шаг существует:
   - 20 карт с известным нам мнением (явно слабые и явно сильные) → Score;
   - 10 боевых сценариев из 51 теста с известным правильным исходом → Noul;
   - 10 ходов ИИ, где мы уверены в правильном ходе → Choice.
4. **Критерий продолжения:** Jev соглашается с известным ответом не реже 17 из 20
   (карты) и 8 из 10 (сценарии). Согласие по ходам оцениваем отдельно: здесь важно не
   «угадал наш ход», а «уверенно указал на ошибку там, где она есть».
5. **Критерий остановки:** если русский текст читается плохо (уверенность низкая,
   ответы бессмысленные) — **останавливаемся и не строим пайплайн**. Варианты тогда:
   переводить состояние на английский (теряется текст способностей), взять только
   направление А (там состояния структурные, почти без прозы), либо отказаться.

### Шаг 2. Пайплайн и отчёты (после прохождения ворот)

1. `scripts/jev/client.mjs` — обёртка над `/v1/systemone`: `choice/score/noul`,
   повторы с backoff на 429/529, порог уверенности.
2. `scripts/jev/extract-cards.mjs` — выгрузка карт в состояние (детерминированно).
3. `scripts/jev/balance-audit.mjs` — направление Б, отчёт «выбросы по цене».
4. `scripts/jev/ai-move-audit.mjs` — направление А, отчёт «спорные ходы Хранителя».
5. Каждый отчёт — markdown-файл в `reports/`, читается человеком, ничего не правит сам.

## 7. Что считается успехом

| Направление | Признак, что сработало | Признак, что нет |
|---|---|---|
| А. Ходы ИИ | найдена хотя бы одна ошибка ИИ, подтверждённая глазами и закреплённая тестом | модель «согласна» со всем подряд, расхождений нет |
| Б. Баланс | список выбросов, где хотя бы 3 карты человек признал действительно несбалансированными | выбросы случайны, повторный прогон даёт другой список |
| В. Правила | хотя бы один пробел в покрытии тестов | расхождения только там, где правы мы |
| Г. Тексты | найдена хотя бы одна реальная двусмысленность | придирки к стилю |

**Проверка устойчивости (обязательна для Б):** тот же набор карт, поданный в другом
порядке и разбитый на другие пачки, должен дать близкий список выбросов. Если ответы
гуляют — рубрика плохая, и её надо переписывать, а не верить числам.

## 8. Риски и что с ними делать

| Риск | Насколько вероятен | Что делаем |
|---|---|---|
| Русский текст понимается плохо | **высокий** — английский основной | калибровка до всего остального; при провале — только направление А или отказ |
| Ответы нестабильны между прогонами | средний | проверка устойчивости; рубрика переписывается |
| Jev расходится с нашими 51 тестом | средний | истина — тесты; расхождение идёт в разбор рубрики, не в код |
| Доступ закроют / сломают | **уже случилось** дважды | все отчёты сохраняются в `reports/`; пайплайн не в рантайме, потеря доступа ничего не ломает в игре |
| Кредит $5 кончится | низкий | весь объём — 0.2% кредита; при исчерпании цена $0.042/Мток всё равно ничтожна |

## 9. Открытые вопросы к человеку

1. **Ключ.** Готов ли ты зарегистрироваться в консоли TypeSafe и положить ключ в
   хранилище? Без него ТЗ остаётся на бумаге.
2. **Язык состояния.** Если русский пойдёт плохо — переводить на английский или
   ограничиться структурными направлениями (А и часть Б)?
3. **Границы доверия.** Подтверждаешь правило «истина — наши тесты, модель только
   указывает, куда смотреть», то есть модель **никогда** не правит баланс сама?
4. **Объём.** Начинаем с направления Б (баланс — дешевле всего и заметнее для игрока)
   или сразу с А (ходы ИИ — ценнее, но больше работы по выгрузке состояния)?
